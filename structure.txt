# Spire Music App - Project Documentation

## Overview
Spire is a React + Vite single-page application for personal music library management with Google Drive integration, Supabase backend, and advanced features like karaoke, radio streaming, and artist photo sync.

## Tech Stack
- **Frontend**: React 18, Vite, React Router v6
- **Styling**: Tailwind CSS, custom glassmorphism components (glasscn)
- **Backend**: Supabase (PostgreSQL, Auth, Edge Functions, Realtime)
- **Storage**: Google Drive API (audio files), Supabase Storage (metadata)
- **Auth**: Supabase Auth with Google OAuth (offline access for Drive)
- **APIs**: iTunes Search, MusicBrainz, Wikidata, Wikipedia, DeepSeek (optional)

## Key Features

### 1. Library Management
- **HomeView**: Grid/list of tracks, artist carousel, search (local + catalog)
- **TrackCard**: Play, add to playlist, delete (owned tracks only)
- **ArtistView**: Artist bio, photo, track list, popular tracks
- **PlaylistsView**: CRUD playlists, add/remove tracks, smart playlists (Recently Played, Recently Added, Favorites)

### 2. Google Drive Integration
- OAuth with offline access (`drive.file` scope)
- Tokens stored in `google_oauth_tokens` table (RLS protected)
- Edge Function `refresh-google-token` handles token refresh server-side
- Audio files uploaded directly to Drive, metadata in Supabase

### 3. Track Deletion (New)
- **Client**: `deleteTrackAndDriveFile(trackId)` calls Edge Function
- **Edge Function** (`delete-track`):
  1. Verifies user JWT
  2. Checks track ownership
  3. Refreshes Google token if expired (server-side client secret)
  4. Deletes file from Google Drive API
  5. Deletes `user_tracks` record
- **UI**: Delete button on TrackCard (hover, owned tracks only), confirmation dialog

### 4. Artist Photo Sync
- Background sync in LibraryContext (`runArtistPhotoSync`)
- Priority chain: MusicBrainz → Wikipedia → Wikidata → iTunes
- Music-only verification (occupation checks)
- Updates `artists.photo_url` column

### 5. Karaoke
- Synced lyrics (LRC format) from multiple sources
- Recording with MediaRecorder (audio + video)
- Recordings stored in IndexedDB, synced to Drive

### 6. Radio
- Streaming from configured stations
- Spatial audio effects (Web Audio API)
- Discord listen-along sync

### 7. Sharing
- Library sharing via Supabase RLS policies
- Shared tracks marked with `isShared` flag

## Database Schema (Key Tables)

```sql
-- User's personal library tracks
user_tracks (
  id uuid PK,
  user_id uuid FK -> auth.users,
  track_id uuid FK -> tracks,
  drive_file_id text,
  uploaded_filename text,
  created_at timestamptz
)

-- Canonical track metadata
tracks (
  id uuid PK,
  canonical_title text,
  canonical_artist text,
  duration_seconds int,
  artist_id uuid FK -> artists,
  itunes_id text
)

-- Artist profiles
artists (
  id uuid PK,
  name text,
  photo_url text,
  bio text
)

-- Google OAuth tokens (RLS: user_id = auth.uid())
google_oauth_tokens (
  user_id uuid PK,
  access_token text,
  refresh_token text,
  expires_at timestamptz,
  scope text,
  token_type text,
  updated_at timestamptz
)

-- Playlists
playlists (id, user_id, title, description, is_public)
playlist_tracks (playlist_id, track_id)

-- Liked songs
liked_songs (user_id, track_id)

-- Listening history
listening_history (user_id, track_id, genre, created_at)
```

```bash
supabase functions deploy delete-track
supabase functions deploy fetch-artist-photo
```
